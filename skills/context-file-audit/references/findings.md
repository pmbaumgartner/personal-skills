# Findings reference — arXiv:2602.11988 (v1, Feb 2026)

"Evaluating AGENTS.md: Are Repository-Level Context Files Helpful for Coding Agents?"
Thibaud Gloaguen, Niels Mündler, Mark Müller, Veselin Raychev, Martin Vechev.
Code: https://github.com/eth-sri/agentbench

Use this file when the user asks *why* a rule exists or disputes a recommendation.

## Experimental setup

- Agents/models: Claude Code + Sonnet-4.5, Codex + GPT-5.2, Codex + GPT-5.1 mini,
  Qwen Code + Qwen3-30b-coder. Default harness settings, temperature 0 (0.7 for Qwen).
- Benchmarks:
  - SWE-bench Lite: 300 tasks, 11 popular Python repos, no developer context files.
  - AGENTbench (new): 138 tasks from 12 niche Python repos, all with developer-committed
    context files. Built from real PRs; LLM-standardized task descriptions; LLM-generated
    then human-curated regression tests (75% avg coverage of modified code).
- Three settings per task: None (context file removed), LLM (generated via each agent's
  recommended /init flow on the pre-patch repo), Human (developer-committed file; AGENTbench
  only).
- Developer context files: mean 641 words, 9.7 sections (min 24 words, max 2003).

## Headline results

| Finding | Numbers |
|---|---|
| LLM-generated files reduce success | -0.5% (SWE-bench Lite), -2% (AGENTbench) avg; drops in 5/8 settings |
| Human files help marginally | +4% avg on AGENTbench; beat LLM files for all 4 agents; no gain for Claude Code |
| Cost overhead, LLM files | +20% (Lite), +23% (AGENTbench); +2.45 and +3.92 steps avg — increase in EVERY setting |
| Cost overhead, human files | +3.34 steps, up to +19% cost |
| Reasoning tokens (adaptive-reasoning models) | LLM files: +22% (GPT-5.2), +14% (GPT-5.1 mini) on Lite; human files: +20% / +2% |

## Mechanism findings (basis for the audit rules)

**Instructions are followed (→ every line has a cost).** `uv` used 1.6x/instance when
mentioned vs <0.01 when not; repo-specific tools 2.5x vs <0.05. So poor outcomes are not an
instruction-following failure — the instructions themselves add work. Basis for R3, R4, R8.

**Overviews don't work.** 95-100% of LLM-generated files (except GPT-5.1 mini, 36%) and 8/12
developer files contained codebase overviews. Measured steps-before-first-touching-a-file-in-the-
gold-patch: presence of a context file did **not** meaningfully reduce it, and often increased it.
GPT-5.1 mini even wasted steps re-finding and re-reading the context file already in its context.
Basis for R1.

**Redundancy.** With all other documentation deleted (`*.md`, `docs/`, examples) after file
generation, LLM-generated context files improved success by +2.7% on average and beat
developer-written docs. I.e., their content is useful *only* when it isn't duplicated elsewhere.
Explains anecdotal wins on poorly documented repos. Basis for R2, R5, R6.

**Behavioral shift.** With context files present, agents run more tests, grep more, read and
write more files, and use more repo tooling — broader exploration without higher resolution.
Basis for R4.

**Generation quality is not the bottleneck.** Files generated by the stronger GPT-5.2 helped on
SWE-bench Lite (+2%) but hurt on AGENTbench (-3%); Codex vs Claude Code generation prompts made
no consistent difference. The problem is the recommended *content pattern* (overview + stack +
guidelines), not the generator. Basis for the anti-pattern section.

## Stated limitations (be honest about these)

- Python only, which is heavily represented in training data; effects may differ (context files
  may help more) for niche languages/toolchains.
- Measures task resolution only — not code style adherence, security, reviewer satisfaction, or
  team-convention compliance. A team may rationally accept ~20% cost for convention adherence;
  the audit should surface that trade-off, not hide it.
- Single sample per task; niche-repo instances used LLM-generated tests (human-curated).
- Paper's own recommendation: skip LLM-generated context files for now; human-written files
  should describe only minimal requirements (e.g., specific tooling).

# Additional literature (added after broader review)

## Lulla et al., arXiv:2601.20404 — "On the Impact of AGENTS.md Files on the Efficiency of AI Coding Agents" (ICSE JAWs 2026)

- Setup: 10 repositories, 124 GitHub PR tasks, GPT-5.2-Codex, paired with/without AGENTS.md,
  isolated Docker, Wilcoxon signed-rank p < 0.05.
- Results: median runtime -28.64%; median output tokens -16.58% (mean -20.08%); input and cached
  input tokens down ~10%; comparable task completion.
- Mean output-token reduction exceeded the median reduction: the savings concentrate in a small
  number of very high-cost runs — the file prevents worst-case exploratory thrash rather than
  uniformly lowering cost.
- Hypothesized mechanism: agents skip exploratory navigation when structure/conventions are
  handed to them.

**Reconciling with Gloaguen (+20% cost):** different agents, repos, and — critically — different
file content. The efficiency win appears when the file substitutes for expensive discovery; the
cost penalty appears when the file adds requirements and generic guidance on top of what the
agent would do anyway. Basis for the audit's core framing: the sign of a context file's cost
impact is determined by its content mix. Do not present either headline number as universal.

## McMillan, arXiv:2605.10039 — factorial study of file-structure variables

- Setup: 1,650 Claude Code CLI sessions, 16,050 function-level observations, two TypeScript
  codebases, 3 models (primarily Sonnet 4.6), 5 tasks. Variables: file size (25/100/250/500
  lines), instruction position (top → bottom, 5 levels), architecture (single CLAUDE.md;
  CLAUDE.md + AGENTS.md; + two nested per-directory files), presence of conflicting instructions.
  Mixed-effects models + Bayesian companion.
- Result: **none** of the four variables nor their two-way interactions produced a detectable
  adherence contrast after multiple-testing correction. Conflict contrast: +0.33pp, p = 0.912.
- What *did* matter: task type, and session length — compliance progressively degrades as the
  agent generates more code within a single session.
- Caveats: single trivial target instruction (an annotation), TypeScript only, mostly one model
  family. Nulls on size/conflict are Bayesian-supported; the others are weaker evidence classes.
- Basis for R9 (emphasis/position theater), R10 (enforce mechanically — prose can't fix
  within-session decay), R11 (don't micro-optimize structure).

## McMillan, arXiv:2602.05447 — structured context engineering at scale

- 9,649 experiments, 11 models, 4 formats (YAML, Markdown, JSON, TOON), schemas 10-10,000
  elements (SQL generation as proxy for programmatic agent operations).
- Result: multi-file organization and retrieval strategy affect accuracy more than serialization
  format. Basis for R11's "format doesn't matter, organization does".

## Agent READMEs, arXiv:2511.12884 — empirical characterization of context files

- Large-scale content analysis of real context files. Build/Run and implementation details
  dominate; non-functional requirements (security 14.5%, performance 14.5%) are rare.
- Files are actively maintained through small, frequent changes — they behave like dynamic
  configuration, not static docs.
- Recommendation adopted by this skill: **configuration-as-code** — review context-file changes
  in PRs with the same rigor as a Dockerfile or CI workflow.

## SWE-Skills-Bench, arXiv:2603.15401 — marginal utility of agent Skills

- 49 public SWE skills × real pinned repos with acceptance-criteria tests, ~565 task instances,
  paired with/without skill.
- Results: 39/49 skills yield zero pass-rate improvement; average gain +1.2%; token overhead
  ranges from modest savings to +451% with unchanged pass rates.
- Basis for R12: moving cut context-file content into Skills is not a free win; the same
  minimalism discipline applies.

## Descriptive context (no causal claims — cite for prevalence only)

- Santos et al., arXiv:2511.09268: 328 CLAUDE.md files; architecture concerns dominate content,
  followed by development guidelines, project overviews, testing.
- Galster et al., arXiv:2602.14690: 2,853-2,926 repos; context files dominate agent configuration
  and are often the sole mechanism; AGENTS.md emerging as the cross-tool standard.
